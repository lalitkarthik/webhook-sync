# Research gaps

Scanned: Q1–Q96, decisions 0001–0007, the design audit, `docs/research/feature-inventory.md` and [razorpay-first-brief.md](razorpay-first-brief.md). Researched in [gaps-stripe.md](../research/gaps-stripe.md), [gaps-google-python-razorpay.md](../research/gaps-google-python-razorpay.md) and [razorpay-first.md](../research/razorpay-first.md); contradictions settled as Q97–Q102 and Q103–Q114. G38, G48 and G49 were closed by the P0 recordings ([tests/recordings/razorpay/README.md](../../tests/recordings/razorpay/README.md)). Updated: 2026-10-03.

**What this page contains.** Every design decision that holds only if a fact about an outside system is true (Stripe, Razorpay, Google, Python and SQLite behaviour, hosting, licences, the market), whether that fact is already sourced, and how to settle it if not.

**How to read it.** Rows that would break the architecture come first, then rows by the earliest build step that depends on them ([build-order.md](build-order.md): P0-P6 of the Razorpay-first cut, then "after pitching", then "Stripe (parked)" for facts only the parked Stripe adapter needs, [Q103](grilling-log.md)). **Check** is `OK` with its source, `RESEARCH` when documentation can settle it, or `SPIKE` when only running code against the real system can. Most SPIKE rows belong in the recording spike ([testing.md](testing.md)).

G5 held, so the prototype gains a minimal sweeper ([Q98](grilling-log.md)).
